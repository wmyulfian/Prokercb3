PANDUAN FIREBASE — PROGRAM KERJA CB3
====================================

PROJECT
- Firebase Project ID: database-gencita
- Domain utama aplikasi: https://www.cb3.web.id
- Hosting/API utama: Vercel
- Firebase Authentication: khusus Admin
- Login Pengurus: internal melalui Vercel API, bukan Firebase Authentication
- Database: Cloud Firestore (default)

A. FIREBASE AUTHENTICATION UNTUK ADMIN
--------------------------------------
1. Buka Firebase Console > Authentication > Sign-in method.
2. Aktifkan Email/Password.
3. Aktifkan Google bila Admin ingin memakai Google Sign-In.
4. Pada Authentication > Settings > Authorized domains, pastikan host yang digunakan sudah terdaftar:
   - www.cb3.web.id
   - pages.cb3.web.id (jika menggunakan GitHub Pages)
   - prokercb3.vercel.app (jika memakai domain Vercel bawaan)
   - wmyulfian.github.io (opsional, jika mengakses domain GitHub Pages bawaan)
5. Buat akun Admin di Authentication > Users.
6. Buat dokumen Firestore users/{UID_ADMIN} dengan field:
   role | string | admin
   nama | string | Administrator

Catatan: akun Firebase Authentication hanya untuk Admin. Jangan membuat akun Firebase Authentication untuk Pengurus pada arsitektur ini.

B. FIRESTORE DATABASE
---------------------
Koleksi utama:
- users/{UID_ADMIN}: profil Admin Firebase Authentication.
- pengurus/{pengurusId}: data umum Pengurus.
- program_kerja/{programId}: program resmi.
- usulan_program/{usulanId}: usulan kegiatan.
- akun_pengurus/{loginName}: akun login internal Pengurus (password hash dan salt, bukan password asli).
- _pengurus_login_limits/{hashIp}: penghitung pembatasan percobaan login.

JANGAN mengisi password asli ke Firestore. Aplikasi menyimpan hasil hash scrypt dan salt di akun_pengurus melalui API server.

C. FIREBASE SERVICE ACCOUNT UNTUK VERCEL API
--------------------------------------------
Vercel API memerlukan Firebase Admin SDK agar dapat memverifikasi akun Admin serta membuat/mengelola akun internal Pengurus secara aman.

1. Buka Firebase Console > Project settings (ikon roda gigi) > Service accounts.
2. Pilih Firebase Admin SDK.
3. Klik Generate new private key dan unduh file JSON.
4. Simpan file JSON itu secara pribadi di komputer.
5. JANGAN mengunggah file JSON tersebut ke GitHub, jangan menaruhnya di index.html, dan jangan mengirimkannya melalui chat.
6. Salin seluruh isi file JSON untuk dimasukkan langsung ke Environment Variable Vercel bernama FIREBASE_SERVICE_ACCOUNT_JSON.

Kunci Service Account adalah kredensial server yang sangat sensitif. Jika pernah terunggah ke repository publik, segera hapus/nonaktifkan key tersebut dan buat key baru.

D. ENVIRONMENT VARIABLES DI VERCEL
-----------------------------------
Buka Vercel Dashboard > project Prokercb3 > Settings > Environment Variables.
Tambahkan variabel berikut untuk Production:

1. Name: FIREBASE_SERVICE_ACCOUNT_JSON
   Value: seluruh isi JSON Service Account yang diunduh pada bagian C.

2. Name: PENGURUS_SESSION_SECRET
   Value: secret acak minimal 48 karakter. Cara membuat dengan Node.js:
   node -e "console.log(require('node:crypto').randomBytes(48).toString('base64url'))"
   Jangan gunakan contoh secret publik dan jangan mengirim nilai ini kepada siapa pun.

3. ALLOWED_APP_ORIGINS (opsional)
   Value: https://www.cb3.web.id,https://pages.cb3.web.id,https://prokercb3.vercel.app
   Origin utama sudah diizinkan di kode; variabel ini hanya untuk origin tambahan.

Pilih Environment Production. Preview dapat ditambahkan jika memang ingin menguji API di deployment preview. Setelah menyimpan atau mengubah Environment Variables, lakukan redeploy karena perubahan tidak berlaku pada deployment yang sudah berjalan.

E. NODE.JS DI VERCEL
--------------------
1. Vercel Dashboard > project Prokercb3 > Settings > General / Build & Development Settings.
2. Pilih Node.js Version: 22.x.
3. Simpan lalu deploy ulang.

Firebase Admin Node.js SDK versi yang digunakan membutuhkan Node.js 22 atau lebih baru. package.json paket ini membatasi ke Node 22 agar konsisten.

F. UPLOAD FILE KE GITHUB DAN DEPLOY
-----------------------------------
Unggah/ganti file berikut ke root repository wmyulfian/Prokercb3:
- index.html
- firestore.rules
- vercel.json
- package.json
- .gitignore
- .env.example
- README.md
- PETUNJUK-FIREBASE.txt
- PETUNJUK-LOGIN-INTERNAL-PENGURUS.md
- folder api/
- folder lib/

Pastikan api/ dan lib/ tetap menjadi folder di root repository, bukan isi file yang dipindah ke index.html.

Jangan unggah file backup index.before-internal-login.html, file JSON Service Account, .env berisi secret, atau node_modules.

Vercel akan menginstal firebase-admin dari package.json dan membangun API routes di folder api/.

G. URUTAN PENERAPAN YANG AMAN
-----------------------------
1. Upload semua file baru ke GitHub.
2. Di Vercel pilih Node.js 22.x.
3. Tambahkan FIREBASE_SERVICE_ACCOUNT_JSON dan PENGURUS_SESSION_SECRET pada Environment Variables.
4. Redeploy proyek Vercel.
5. Uji Admin login dan pastikan dashboard Admin masih terbuka.
6. Baru buka Firestore > Rules, ganti seluruh aturan lama dengan isi firestore.rules terbaru, lalu Publish.
7. Uji Admin sekali lagi.
8. Admin membuat satu akun Pengurus dari menu Database Pengurus.
9. Uji login Pengurus, pembatasan program, usulan, dan ganti password.

H. MEMBUAT AKUN PENGURUS
------------------------
Pengurus TIDAK dibuat di Firebase Authentication dan TIDAK membutuhkan dokumen users/{UID}.

Untuk Pengurus baru:
1. Admin login menggunakan Firebase Authentication.
2. Buka Database Pengurus > Tambah Pengurus.
3. Isi nama, jabatan, bidang, nama login unik, dan password awal minimal 10 karakter.
4. Klik Simpan Pengurus.
5. Vercel API membuat dokumen pengurus/{pengurusId} dan akun_pengurus/{loginName} secara bersamaan.
6. Admin menyampaikan nama login dan password awal kepada Pengurus secara pribadi.

Untuk data Pengurus lama yang sudah ada tanpa akun internal:
1. Di tabel Database Pengurus klik tombol Buat akun.
2. Masukkan nama login dan password awal minimal 10 karakter.
3. API akan menghubungkan akun dengan dokumen Pengurus lama.

Pengurus login dengan tab Pengurus menggunakan nama login dan password. Google Sign-In hanya untuk Admin.

I. GANTI PASSWORD DAN PENGELOLAAN AKUN
--------------------------------------
- Pengurus dapat masuk ke menu Ganti password di sidebar, mengisi password saat ini dan password baru (minimal 10 karakter).
- Admin dapat Reset password dari Database Pengurus.
- Admin dapat mengaktifkan atau menonaktifkan akun. Penonaktifan mencabut sesi aktif.
- Sesi Pengurus menggunakan cookie HttpOnly Secure dan masa berlaku 8 jam.

J. BATASAN DAN PERINGATAN
-------------------------
- Admin tetap membaca/menulis data organisasi langsung melalui Firebase Web SDK; Firestore Rules memeriksa users/{UID_ADMIN}.role == admin.
- Browser Pengurus tidak membaca Firestore secara langsung. Seluruh data Pengurus diambil melalui Vercel API yang memverifikasi cookie sesi.
- Pengurus hanya menerima program dengan penanggungJawabId yang cocok dengan pengurusId akun tersebut, serta usulan miliknya sendiri.
- Admin SDK melewati Firestore Security Rules. Karena itu endpoint API melakukan verifikasi Admin/sesi sebelum mengakses database.
- Jangan pernah memakai aturan terbuka seperti allow read, write: if true.
- Jangan pernah menyimpan password asli. Simpan hanya hash + salt di akun_pengurus.
- Jangan membagikan Service Account JSON atau PENGURUS_SESSION_SECRET.
- GitHub Pages hanya hosting statis alternatif. API autentikasi Pengurus tetap berjalan di Vercel melalui https://www.cb3.web.id.
